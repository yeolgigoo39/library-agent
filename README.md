# 도서관 사서 보조 에이전트

수업의 `project_4/05_full_agent.py`를 바탕으로 구현한 LangChain 싱글 에이전트 과제입니다. Ollama에서 Qwen3 모델을 실행하여 도서 검색, 추천, 본인 대출 조회, 예약, 시설·규정 안내를 제공합니다.

## 실행 방법

Python 3.12와 Ollama가 설치되어 있어야 합니다. Ollama를 실행한 상태에서 다음 명령을 프로젝트 폴더에서 실행합니다.

```powershell
ollama pull qwen3:4b-instruct-2507-q4_K_M
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe 05_full_agent.py
```

검증에 사용한 주요 버전은 Python 3.12.10, langchain 1.4.9, langchain-ollama 1.1.0, langgraph 1.2.20, pydantic 2.14.3입니다. requirements.txt는 버전을 고정하지 않으므로 설치 시점에 따라 환경이 달라질 수 있습니다. Gemini API 키는 사용하지 않습니다. 종료하려면 `종료`를 입력합니다.

## 사용 예시

- `2열람실 자리 있어?`
- `대출 기간이랑 반납 규정 알려줘`
- `이도윤 작품 알려줘`
- `내 대출 기록 알려줘`
- `시간을 파는 서점과 비슷한 다른 작가 책 3권 추천해줘`

## 파일 구성

| 파일 | 역할 |
|---|---|
| 05_full_agent.py | 모델·도구·미들웨어 조립 및 터미널 실행 |
| models.py | 과제 지정 Ollama 모델 설정 |
| context.py | 사서와 이용자의 실행 정보 타입 |
| middleware.py | 입력 차단, 시설·규정 직접 연결, 정보 주입, 출력 검수, 기억 |
| tools.py | 도서관 기능을 에이전트 도구로 제공 |
| catalog.py / library_books.txt | 도서 목록, 대출, 좌석, 규정 자료 |
| recommend.py | 같은 작가 제외 및 기존 추천 점수 계산 |

## 설계와 개선 과정

질문을 먼저 검사한 뒤 시설·규정 질문은 해당 도구로 직접 전달합니다. 나머지는 실행 정보와 기억을 제공받은 모델이 도구를 선택하고 결과를 안내합니다. 마지막으로 타인 대출 정보가 포함되었는지 검사합니다.

초기 구현에서는 모델을 이용한 출력 검수가 정상 좌석 안내까지 차단했습니다. 이를 규칙 기반 검사로 바꾸었습니다. 시설 질문에서 도구를 사용하지 않는 문제는 직접 연결 경로로 보완했습니다. 컨텍스트 타입을 `ToolRuntime[Context]`로 지정하고, 저장된 선호 주입, 대출 가능한 책의 예약 안내, 단일 추천 도구 결과 보존도 수정했습니다.

## 최초 확대 평가 결과

2026-11-06의 코드 상태에서 실제 에이전트 시나리오 50개와 내부 기능 검사 50개를 실행했습니다.

| 기준 | 결과 |
|---|---|
| 답변 내용 정답 | 40/50 (80%) |
| 내용·필수 도구·조회 근거 일치 | 38/50 (76%) |
| 필수 도구 사용 | 44/50 (88%) |
| 내부 기능 검사 | 48/50 (96%) |

첫 세 지표는 같은 50개 응답을 서로 다른 기준으로 평가한 값입니다. 전체 프로그램이 중단되는 예외는 없었지만, 선호 저장 시 도구 입력 오류 2회 후 재시도로 성공한 사례가 있었습니다. 이 결과는 준비한 시나리오의 단회 측정이며 모든 질문의 정확도나 개인정보 보호를 보장하지 않습니다.

이 평가에서 연체 규정의 잘못된 안내, 미등록 도서의 부분 검색 오인, 예약 대상 오해, 도서 검색 요청의 정책 오탐, 복합 질문의 일부 누락과 추천 설명 변경을 발견했습니다.

## 후속 수정과 재검증

예약은 질문에 명시된 정확한 제목 한 권과 신청 의사가 확인될 때만 처리하도록 보완했습니다. 단어 일부가 겹치는 미등록 책을 다른 책으로 찾지 않도록 검색을 수정했습니다. '오늘'만으로 운영시간 질문으로 분류하지 않으며, 주식 관련 도서 검색과 투자 조언 요청을 구분합니다.

기존 입력 미들웨어에서 명확한 요청에 필요한 도구 호출을 구성하여 LangChain의 도구 실행 경로로 전달합니다. 시설·규정만 묻는 경우는 기존처럼 직접 안내합니다. 여러 도구가 반환한 도서관 결과를 최종 답변에 함께 보존한 뒤 타인 대출 정보 검사를 적용합니다. 모델, 추천 계산, 같은 작가 제외 규칙, `create_agent` 조립 구조는 유지했습니다.

| 최종 코드 검사 | 통과 |
|---|---|
| 기존 실제 질문 재검사: 내용 및 필수 도구 | 50/50 |
| 내부 기능 검사 | 50/50 |
| 추가 표현: 답변과 실제 예약 상태 확인 | 20/20 |
| 원래 요청과 다른 예약·부정문·방법 문의의 상태 변경 방지 | 4/4 |

답변 내용도 직접 검토했습니다. 개발 도중 단어 포함 여부만 확인하는 검사에서 놓친 불필요한 도서 조회와 예약 부정문 안내 오류를 찾아 보완했습니다. 수정한 세 모듈의 compileall 검사를 통과했고, 최종 평가 중 Pydantic 직렬화 경고는 수집되지 않았습니다.

이는 알려진 실패를 수정한 뒤 같은 질문과 추가 표현을 확인한 결과로, 새로운 모든 질문에 대한 100% 정확도를 의미하지 않습니다. 기억 저장 시 도구 입력 형식 오류 2회 후 자동 재시도로 성공하는 문제와 종료 시 소켓 ResourceWarning은 남아 있습니다. 제목 없는 후속 예약은 정확한 제목을 다시 요청하며, 복잡한 다단계 요청 전체에 대한 성공은 보장하지 않습니다.

도서 26권과 시설·규정·대출 정보는 프로젝트에 준비한 예시 자료이며 실제 도서관 시스템과 연결되지 않습니다. 이용자 설정에는 과제 작성자의 이름과 학번이 포함됩니다. 기억과 변경된 예약 상태는 메모리에 보관되므로 프로그램을 종료하면 유지되지 않습니다.
